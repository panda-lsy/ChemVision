# 开源治理、权利清单与维护计划

## 当前情况

原 README 选择 MIT，但缺少根 LICENSE；本轮补全标准文本，适用项目有权许可的自有代码，不能代替权利人授权。现有 Git 账号记录不能证明大学项目合同、厂商 SDK、图片及他人贡献全部可开源。

| 对象 | 当前依据 | 剩余动作/公开条件 |
| --- | --- | --- |
| 自有 Dart/桥接/文档 | README 既有 MIT 选择；补全根 LICENSE | 全部权利人确认，核对学校/实验室/项目合同；确认前不声称授权链完整 |
| Ketcher | 既有 NOTICE 指向 EPAM Apache-2.0；保留 JS 第三方许可碎片 | 已下载官方当前 LICENSE/NOTICE；旧 bundle 的准确构建版本与原始来源仍需核对 |
| SmilesDrawer | 官方 MIT；本地已有 bundle | 已补官方许可文本；本地版本/来源哈希对应仍待核对 |
| Dart/Flutter 依赖 | pubspec.lock、本机 package_config 与许可文件盘点 | 报告是文件存在性检查；需保留实际发行包的许可集合，复核传递依赖与漏洞 |
| DECIMER 代码/模型 | 外部项目上游 MIT，锁定 decimer==2.8.0 | 分别核对实际模型权重、训练数据、版本与引用，不把代码许可自动推广到全部数据 |
| BlueLM AAR | 已跟踪 `android/app/libs/llm-sdk-release.aar`，未找到可再分发许可 | 负责人取得厂商授权或决定独立、可复现的可选集成方式；本轮不擅自删除功能/二进制 |
| 图标、器材 SVG/素材 | 未见完整来源/授权台账；器材目录是他人未提交开发 | 提供来源、作者、许可、改动、是否允许公开；不默认上传 |
| 根目录合同/承诺书及 doc/outputs | 私人材料，可能涉及权利约定与个人信息 | 不打包、不复制内容到参赛文件；由权利人审查限制并给结论 |
| 用户反馈/课堂图片 | 未取得可公开验证的同意与记录 | 匿名化不能替代所有授权；使用前记录用途和公开范围 |

许可来源与校验摘要见 `third_party/licenses/sources.json`。Ketcher 官方 NOTICE 列出多种依赖许可，不能仅靠顶层 Apache 声明认定其全部传递依赖合规。新增声明不是完整 SBOM 或法律意见。

## 已补的治理设施

- 根 `CONTRIBUTING.md`、`SECURITY.md`、Issue/PR 模板。
- 新 Quality 工作流：分析、测试、秘密模式/静态 HTML 资源检查、Web 编译，读取权限，无部署步骤。
- 原构建发布流水线保留。它在 main 推送时自动改版本/部署/发版；本轮未触发远端操作。新门禁是独立检查，尚未配置成分支保护或原发布作业依赖，不能声称已阻断所有发布。
- 测试桩与真实服务证据分开；每项能力可回指代码、输入、配置及日志。

## 待执行的维护机制（非既有社区运营成果）

负责人在提交前填入真实维护者和备份维护者，约定每周一次问题分拣。普通改动由维护者审阅；化学结论请领域人员复核；许可/权限/数据流改动单独复查。接受小范围缺陷修复、知识点纠错、测试样本和文档贡献。无法承诺已经存在教师专家组、合作院校或响应 SLA。

Issue 标签建议：`bug`、`chemistry`、`documentation`、`security`（敏感内容走私密渠道）、`good first issue`。在实际仓库权限与维护者确认后设置标签；本轮未更改远端。
